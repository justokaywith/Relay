# Contributing to Relay

Thanks for helping make multi-agent work easier to follow.

This repository accepts documentation improvements, clearer setup examples, reproducible bug reports and feature suggestions. The hosted application’s source code remains private.

## Start small

Follow the [first contribution guide](docs/CONTRIBUTOR-QUICKSTART.md) for browser-only editing or Git commands. No application build is needed. Check [good first issues](https://github.com/justokaywith/Relay/labels/good%20first%20issue) for scoped documentation work.

## Before opening an issue

1. Read the [Quick start](docs/QUICKSTART.md) and [FAQ](docs/FAQ.md).
2. Search existing issues and Discussions.
3. Choose the bug report, documentation, integration or feature request template.
4. Explain your workflow and what happened using sanitized examples.

Do not include API keys, runner keys, passwords, private conversations, account emails, customer data or full diagnostic dumps. Redact screenshots before uploading them.

Use [private vulnerability reporting](https://github.com/justokaywith/Relay/security/advisories/new) for security concerns.

## Documentation pull requests

Keep changes focused. Check links, use placeholders for secrets and distinguish released behaviour from ideas or unverified integrations.

Please do not add application source, compiled binaries, tracking scripts, dependency installers, real credentials or unrelated promotional links.

Configuration examples are welcome when they are accurate, clearly labelled and contain no populated secrets. Explain which client, operating system and connection type the example targets.

## Review checklist

- **Accuracy:** match the current product and explicitly label previews.
- **Reproducibility:** identify the client/version, operating system and connection type.
- **Privacy:** use placeholders and remove private details.
- **Scope:** one focused change; application source remains private.
- **Validation:** preview Markdown, open links and parse configuration examples.

Maintainers may request changes. Reply in the pull request and explain any tradeoffs; a smaller, verified improvement is easier to review.

## Community expectations

Follow our [Code of conduct](CODE_OF_CONDUCT.md). Be specific, constructive and respectful. Describe the problem rather than attacking people. Maintainers may remove spam or content that exposes private information.

We do not promise an implementation date for every request. Useful examples and reproducible reports help us prioritize.
